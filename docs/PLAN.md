# Taskbar Office 계획

Orca에서 돌아가는 에이전트 세션을 작업표시줄 위의 작은 픽셀아트 사무실로 보여주는 데스크톱 위젯.

- 상태: 5단계까지 구현 완료. 마우스 조작이 필요한 항목(드래그 폭 조절, 트레이 메뉴, 설치)은 직접 확인 대기
- 최종 수정: 2026-11-11

## 1. 확정된 결정

| 항목 | 결정 |
|---|---|
| 시점/그림체 | 옆에서 본(사이드뷰) 픽셀아트 |
| 창 배치 | 작업표시줄 바로 위, 모니터 전체 폭의 투명 띠. 항상 위, 빈 공간은 클릭 통과 |
| 크기 조절 | 배율(픽셀 확대 2~6배)로 높이 조절, 띠의 폭과 좌우 위치도 조절 가능. 설정은 저장되어 재시작 후 유지 |
| 모니터 선택 | 다중 모니터일 때 띠를 띄울 모니터를 트레이 메뉴에서 선택. 선택한 모니터가 분리되면 주 모니터로 복귀 |
| 상호작용 | 호버 = 툴팁, 클릭 = Orca에서 해당 세션의 워크스페이스 열기(세션 탭까지는 Orca가 지원하지 않음). 지시/실행/중지는 하지 않음 |
| 기술 스택 | Electron + TypeScript, 렌더링은 Canvas 2D |
| 캐릭터 단위 | 에이전트 세션 1개 = 캐릭터 1명 |
| 아트 에셋 | 코드로 직접 그린 스프라이트 (나중에 교체 가능한 구조) |
| 알림 | 말풍선 + 캐릭터 동작만. 효과음, Windows 알림 없음 |

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│  공용테이블 화이트보드 빈백 스탠딩 책상 │문│ 커피 수다테이블 소파 화분 헬스장 │
│   오피스 (작업 중인 세션)                    라운지 (쉬는 세션)        │
└──────────────────────────────────────────────────────────────────────┘
══════════════════════ Windows 작업표시줄 ══════════════════════════════
```

- 기본 높이 약 140px(픽셀 4배 확대 기준 35px 높이의 장면). 기본 폭은 선택한 모니터의 작업 영역 전체.
- 크기 조절: 배율을 바꾸면 높이가 정수배로 변함(픽셀이 뭉개지지 않게 정수 배율만). 폭은 띠 양 끝을 드래그하거나 설정에서 전체/절반/사용자 지정으로 변경. 폭이 줄면 책상 수와 라운지 가구가 그에 맞춰 줄어듦.
- 모니터 선택: 트레이 메뉴에 모니터 목록 표시. 모니터마다 배율(DPI)과 작업표시줄 위치가 다를 수 있으므로 선택한 모니터의 작업 영역 기준으로 다시 배치.
- 왼쪽 약 60%가 오피스, 오른쪽 약 40%가 라운지.
- 오피스는 실리콘밸리 IT기업 느낌으로 자리 종류를 섞음: 일반 책상(의자+모니터), 스탠딩 데스크, 공용 테이블(2~3인, 노트북), 빈백(무릎 위 노트북). 사이사이에 화분과 화이트보드.
- 가구는 문에서 왼쪽으로 정해진 순서(`scene.ts`의 `OFFICE_PATTERN`)대로 놓고 폭이 남는 만큼 반복. 작업을 시작한 캐릭터는 빈 자리 중 아무 곳이나 골라 앉아, 자리 종류에 맞는 자세로 일함.
- 자리보다 작업 중인 세션이 많으면 문 근처에 서서 태블릿으로 일함.

## 3. 캐릭터 상태와 동작

| Orca 세션 상태 | 캐릭터 위치/동작 | 말풍선 |
|---|---|---|
| 작업 중 | 책상으로 걸어가 앉아서 타이핑 | `...` 애니메이션 + 사용 중인 도구 아이콘 |
| 응답 대기 (권한 요청, 질문) | 책상에서 일어나 손 흔들기 | `❗` |
| 방금 완료 | 만세 동작 후 라운지로 이동 | `✅` (확인하거나 일정 시간 지나면 사라짐) |
| 실패/중단 | 책상에서 머리 긁적이기 | `⚠` |
| 대기 (완료 후 한가함) | 라운지에서 커피 마시기, 소파 앉기, 서성이기, 서로 잡담 | 없음 |
| 오래된 완료 세션 | 문으로 나가 퇴근 (화면에서 사라짐) | 없음 |

- 에이전트 종류별 외형: Claude, Codex, Gemini(Antigravity) 등 종류마다 옷 색을 다르게, 같은 종류 안에서는 머리 모양/색으로 구분. 세션 ID를 시드로 써서 같은 세션은 항상 같은 얼굴.
- 호버 툴팁: 워크스페이스 이름, 대화 제목, 에이전트 종류, 상태 경과 시간, 마지막 메시지 한 줄.
- 퇴근 기준(초안): 완료 후 30분 이상 지났고 읽지 않음 표시가 없는 세션. 화면에 남는 인원 상한 12명.

## 4. 데이터 소스

`orca worktree ps --json`으로 워크스페이스별 에이전트 목록을 읽을 수 있음을 확인함. 세션마다 다음 필드가 옴:

- `paneKey` (세션 식별자), `agentType` (`claude`, `codex` 등)
- `state`, `mainAgent.outcome`, `stateStartedAt`, `updatedAt`, `interrupted`
- `conversationName`, `prompt`, `lastAssistantMessage`, `toolName`
- `activity.unread`, `children` (서브에이전트)

1차는 2~3초 간격 폴링. 이전 스냅샷과 비교해 상태 변화 이벤트(시작, 완료, 응답 대기)를 만들어 렌더러로 보냄.

### 0단계 검증 결과 (2026-11-11, Orca 1.4.255)

**1. 상태 값: 확정**

Orca 플러그인 타입 정의(`resources/plugins/types/orca-host.d.ts`)에 명시돼 있음.

- `state`: `working` | `blocked` | `waiting` | `done`
- `mainAgent.outcome`: `success` | `failure` | `cancellation` | `superseded` | `interruption` | `unconfirmed`

실제 출력에서 `working`(도구 실행 중이면 `toolName`에 도구 이름)과 `done`/`success`를 확인함. `blocked`와 `waiting`은 실제로 관찰하지 못해 둘의 차이는 미확인. 둘 다 "응답 대기"로 묶어 `❗`로 처리하고, 3단계에서 실제 권한 요청을 띄워 구분되는지 확인.

| Orca 값 | 캐릭터 상태 |
|---|---|
| `working` | 작업 중 |
| `blocked`, `waiting` | 응답 대기 |
| `done` + `success` | 완료 |
| `done` + `failure` | 실패 |
| `done` + `cancellation`, `interruption`, 또는 `interrupted: true` | 중단 |
| `done` + `superseded`, `unconfirmed` | 완료로 취급하되 `✅` 없이 라운지로 |

**2. 세션 이동: 워크스페이스까지만 가능**

- `orca worktree activate --worktree id:<worktreeId>`가 동작함(현재 워크스페이스로 시험, `activated: true`). 워크스페이스 단위로 열림.
- 채팅형 세션 탭을 직접 여는 CLI 명령은 없음. `chat` 명령은 `rename`뿐.
- 터미널형 에이전트는 `orca terminal switch --terminal <handle>`로 탭까지 이동 가능. 단 에이전트 행(`paneKey`)과 터미널 핸들을 잇는 방법은 미확인.
- 폴더 워크스페이스는 CLI로 활성화 불가(도움말에 명시). 현재 워크스페이스 6개는 모두 `git` 종류라 해당 없음.
- 미확인: Orca 창이 다른 창 뒤에 있을 때 `activate`가 창을 앞으로 가져오는지. 안 가져오면 4단계에서 Orca 창을 직접 앞으로 올리는 처리를 추가.

결정: 클릭 = 해당 워크스페이스 열기. 터미널형 세션은 가능하면 탭까지 이동.

**3. 폴링 비용: 문제없음**

- `orca worktree ps --json` 1회에 약 400~530ms(6회 측정, 워크스페이스 6개/세션 8개). CPU 사용량은 측정하지 않음.
- 3초 간격 폴링으로 시작. 호출이 겹치지 않게 이전 호출이 끝난 뒤 다음 호출을 예약.
- 대안: Orca 플러그인 API에 `agent.status.changed` 이벤트와 `workspace.open` 메서드가 있음. 폴링 지연(최대 3초)이 거슬리면 Orca 플러그인을 만들어 이벤트를 받는 방식으로 전환 가능. 지금은 조사만 해둠.

**4. 원격 호스트: 1차 제외**

- 기본 호출은 `local`만 반환. 원격 2개는 `--environment 92`, `--environment 9`로 따로 호출해야 함.
- 0단계에서는 시험하지 않았으나, 이후 4.5단계에서 원격 환경 조회를 구현함(6장 참고).

## 5. 구조

```
orca-taskbar-office/
├─ docs/PLAN.md
├─ src/
│  ├─ main/            Electron 메인 프로세스
│  │  ├─ window.ts       투명 띠 창, 작업표시줄 위 배치, 클릭 통과
│  │  ├─ settings.ts     배율, 폭, 위치, 모니터 설정 저장/불러오기
│  │  ├─ orca-poller.ts  orca CLI 호출, 스냅샷 비교, 이벤트 생성
│  │  ├─ orca-actions.ts 클릭 시 Orca 세션으로 이동
│  │  └─ tray.ts         트레이 아이콘 (숨기기, 종료, 시작 시 실행)
│  ├─ shared/types.ts  세션 상태 타입, IPC 메시지
│  └─ renderer/        Canvas 장면
│     ├─ scene.ts        배경, 가구, 자리 배치
│     ├─ character.ts    상태 기계 (걷기, 앉기, 타이핑, 쉬기)
│     ├─ sprites/        픽셀 데이터와 팔레트 (코드로 정의)
│     ├─ bubble.ts       말풍선
│     └─ tooltip.ts      호버 툴팁
└─ package.json
```

- 메인과 렌더러는 IPC로 "세션 목록 스냅샷"만 주고받음. 렌더러는 Orca를 모름.
- 렌더러는 가짜 데이터로도 돌아가게 해서, Orca 없이 애니메이션만 따로 개발/확인 가능.
- 클릭 통과: 기본은 창 전체가 마우스 무시, 커서가 캐릭터 위에 올라갈 때만 입력을 받도록 전환.

## 6. 단계

### 0단계: 검증 (완료)
- 결과는 4장 참고. 상태 값 표와 세션 이동 방식 확정.

### 1단계: 빈 창 (완료, 사용자 확인 끝)
- 실행: `npm start` (빌드 후 실행). 설정 파일은 `%APPDATA%\orca-taskbar-office\settings.json`.
- 확인됨(화면 캡처): 작업표시줄 바로 위 투명 띠 표시, 설정 파일의 배율/폭/정렬이 재시작 후 반영됨(6배, 절반 폭, 오른쪽 정렬로 시험).
- 직접 확인 필요: 빈 공간 클릭 통과, 임시 캐릭터 호버/클릭, 트레이 메뉴(크기, 폭, 위치, 모니터 전환), 모니터 분리 시 주 모니터 복귀.
- 벽은 그리지 않고 바닥과 가구만 그림. 띠가 뒤 창을 가리지 않게 하기 위함. 2단계에서 벽을 넣을지 결정.
- Electron 프로젝트 생성, 작업표시줄 위 투명 띠 창, 항상 위, 클릭 통과, 트레이 아이콘.
- 설정 저장소(배율, 폭, 위치, 모니터)와 트레이 메뉴의 배율/모니터 선택. 모니터 연결/분리, 해상도 변경 시 자동 재배치.
- 완료 조건: 띠 창이 뜨고 뒤의 창을 평소처럼 클릭할 수 있음. 트레이에서 배율과 모니터를 바꾸면 즉시 반영되고 재시작 후에도 유지됨.

### 2단계: 사무실과 캐릭터 (구현 완료)
- 가짜 세션은 메인 프로세스(`src/main/demo.ts`)가 만들어 `sessions` 채널로 보냄. 3단계에서 Orca 폴러가 같은 채널을 씀.
- 창이 포커스를 받지 않아 키 입력 대신 트레이의 "데모" 메뉴로 상태를 바꿈(자동 데모, 출근, 작업 시작, 응답 대기, 완료, 실패, 중단, 퇴근).
- 확인됨(화면 캡처): 책상 타이핑과 `...` 말풍선, 모니터 켜짐, 응답 대기 손 흔들기와 `❗`, 완료 만세와 `✅`, 중단 표시, 라운지 서성이기/소파/커피.
- 오피스 자리 다양화(피드백 반영): 책상, 스탠딩 데스크, 공용 테이블, 빈백 네 종류의 자세와 화면 켜짐을 캡처로 확인. `TASKBAR_OFFICE_DEMO=busy` 환경변수로 실행하면 12명이 모두 작업 중인 상태로 고정되어 자리별 자세를 한 번에 볼 수 있음.
- 캡처로 확인 못 함: 실패 시 머리 긁적이기 동작, 출퇴근 때 문에서 나타나고 사라지는 효과, 책상이 모자랄 때 서서 일하는 자세.
- 계획에서 달라진 점: 작업 중 말풍선은 `...`만 표시. 도구 아이콘은 3단계에서 실제 도구 이름을 본 뒤 추가. 실패는 `✕`, 중단은 `Ⅱ`로 구분.

원래 계획:
- 배경, 책상, 라운지 가구 스프라이트. 캐릭터 걷기/앉기/타이핑/커피 애니메이션.
- 가짜 세션 데이터로 상태 전환 시연.
- 완료 조건: 키 입력으로 상태를 바꾸면 캐릭터가 라운지와 책상을 오가고 말풍선이 뜸.

### 3단계: Orca 연결 (구현 완료)
- `src/main/orca-poller.ts`가 3초마다 `orca worktree ps --json`을 호출해 세션 목록을 만듦. 공급원 전환은 `source.ts`, 현재 목록 보관과 전달은 `session-hub.ts`.
- 기본은 Orca 연결. 트레이의 "데모 모드"를 켜면 가짜 세션으로 전환(설정에 저장됨).
- 퇴근 규칙: 끝난 지 30분이 지났고 읽지 않음 표시가 없는 세션은 제외. 인원 상한 12명이며 작업 중/응답 대기 세션은 상한과 관계없이 모두 표시.
- Orca 호출이 3번 연속 실패하면 사무실을 비우고 트레이에 "Orca 연결 안 됨" 표시. 다시 연결되면 자동 복구.
- 트레이 툴팁과 메뉴 첫 줄에 연결 상태 표시(작업 중 수, 표시/전체 수).
- 확인됨: 실제 Orca 세션 8개 중 작업 중인 1개만 표시되고(나머지 7개는 끝난 지 1시간 이상), 그 캐릭터가 자리에서 `...` 말풍선과 함께 일하는 모습을 캡처로 확인.
- 확인 못 함: 실제 세션의 완료 전환(만세 후 라운지 이동), 응답 대기(`blocked`/`waiting`) 표시, Orca 종료 시 사무실 비우기.
- 미룸: 말풍선의 도구 아이콘은 5단계로.

원래 계획:
- 폴러 구현, 실제 세션 상태를 캐릭터에 연결, 퇴근 규칙 적용.
- 완료 조건: Orca에서 에이전트를 시작하면 캐릭터가 책상으로 가고, 끝나면 `✅` 후 라운지로 감.

### 4단계: 상호작용 (구현 완료)
- 툴팁은 별도의 작은 창(`src/main/tooltip.ts`)으로 띠 위에 띄움. 띠 창은 높이가 낮고 픽셀 캔버스라 한글 글자를 담을 수 없기 때문.
- 툴팁 내용: 에이전트 종류 배지, 워크스페이스, 대화 제목, 상태와 경과 시간(작업 중이면 도구 이름 포함), 마지막 응답 첫 줄.
- 커서가 올라간 캐릭터는 걷다가도 멈춰 서서 클릭하기 쉽게 함.
- 클릭(`src/main/orca-actions.ts`): `orca worktree activate`로 워크스페이스를 열고, 동시에 Orca 창을 앞으로 가져옴. 창 전환은 PowerShell로 Win32 `SetForegroundWindow`를 호출(Alt 키 입력을 흉내 내 Windows의 전경 창 제한을 우회).
- 확인됨: 툴팁 창의 모양과 위치(캡처), Orca 창 앞으로 가져오기(Chrome이 앞에 있던 상태에서 Orca로 전환됨, 약 0.3초).
- 확인 못 함: 실제 마우스 호버로 툴팁이 뜨고 사라지는 흐름, 캐릭터 클릭부터 워크스페이스 전환까지의 전체 흐름. 마우스를 직접 움직여야 해서 사용자 확인 필요.

원래 계획:
- 호버 툴팁, 클릭 시 Orca 세션으로 이동.
- 완료 조건: 캐릭터를 클릭하면 Orca가 앞으로 오면서 해당 세션의 워크스페이스가 열림.

### 4.5단계: 원격 환경 세션 (구현 완료)
- Orca에 저장된 원격 환경(`orca environment list --json`, 현재 9, 91, 92 세 곳)의 세션도 사무실에 표시. 환경 목록은 1분마다 다시 읽음.
- 폴러가 이 PC와 각 원격 환경을 3초마다 동시에 조회(`orca worktree ps --json --environment <id>`). 원격 조회 1회 약 380ms로 로컬과 비슷함.
- 한 곳의 조회가 실패해도 나머지는 그대로 표시. 실패한 곳은 3번 연속 실패 전까지 직전 결과를 유지.
- 퇴근 규칙과 인원 상한(12명)은 로컬과 원격을 합쳐서 적용.
- 트레이 "원격 환경" 메뉴에서 환경별로 표시 여부를 켜고 끔(설정에 저장). 상태 줄에 연결된 원격 수 표시.
- 툴팁의 워크스페이스 옆에 "원격 92"처럼 환경 이름 표시. 클릭하면 `--environment`를 붙여 이 PC의 Orca 창에서 그 원격 워크스페이스를 엶.
- 확인됨: 로컬 8개와 원격 11개, 합계 19개 세션 중 4개가 표시되고 작업 중 2명(로컬 1, 원격 9번 1)이 자리에서 일하는 모습을 캡처로 확인.
- 확인 못 함: 원격 캐릭터 클릭 시 워크스페이스 전환, 트레이에서 환경을 껐을 때 해당 캐릭터가 퇴근하는 것, 원격 연결이 끊겼을 때의 동작.

### 읽지 않은 완료 세션 (피드백 반영, 구현 완료)
- 끝났지만 Orca에서 아직 확인하지 않은 세션은 확인할 때까지 결과 표시(`✅`, 실패 `✕`, 중단 `Ⅱ`)를 계속 달고 까딱이며, 30분 규칙과 인원 상한에 관계없이 퇴근하지 않음. 툴팁에 "아직 확인 안 함" 표시.
- 원인: 원격 환경 조회에는 세션별 읽음 정보(`activity.unread`)가 없고 워크스페이스 단위의 `unread`만 옴. 그래서 원격 세션은 읽지 않음으로 인식되지 않았고, `✅`도 20초 뒤 사라졌음.
- 처리: 세션별 정보가 없으면 워크스페이스의 `unread`를 그 워크스페이스에서 가장 최근에 끝난 세션에 적용.
- 확인됨: 읽지 않은 "GPU Decoding (9)" 세션의 캐릭터가 라운지에서 `✅`를 달고 있는 모습을 캡처로 확인.
- 확인 못 함: Orca에서 확인한 뒤 표시가 사라지는 것.

### 알려진 문제와 수정 (2026-11-12)
- 툴팁이 한 번만 뜨던 문제(수정): 툴팁 창이 숨겨진 동안에는 `requestAnimationFrame`이 돌지 않아 높이 보고가 오지 않았고, 그래서 다시 표시되지 않았음. 높이를 즉시 계산해 보고하도록 바꿈. 표시→숨김→표시를 세 번 반복해 매번 뜨는 것을 캡처로 확인.
- 원격 세션 클릭 시 워크스페이스로 이동하지 않던 문제(수정):
  - 원인: `orca worktree activate --environment <id>`는 `activated: true`를 반환하지만 이 PC의 Orca 화면은 바뀌지 않음. 환경 지정 없이 호출하면 `selector_not_found`.
  - 시도했다가 버린 방법: Orca 플러그인(`workspace.open`). 플러그인의 `workspace.list`에는 이 PC의 워크스페이스만 나오고, 원격 id로 `workspace.open`을 부르면 `selector_not_found`. 플러그인은 Orca에서 내리고 폴더도 삭제함.
  - 채택한 방법: 화면을 원격 쪽으로 옮기는 CLI 명령은 `terminal switch --environment`뿐임. 그래서 원격 워크스페이스에 임시 터미널("Taskbar Office")을 만들고 → 그 터미널로 전환하고 → 터미널을 닫음. 닫은 뒤에도 화면은 그 워크스페이스에 남음. `src/main/orca-actions.ts`의 `openRemote`.
  - 확인됨: 실제 앱 코드로 92번 환경의 워크스페이스를 열었을 때 약 1.8초 걸렸고, 로컬 활성 워크스페이스가 해제되었으며(화면이 원격으로 이동), 임시 터미널이 남지 않음. 9번 환경으로 시험했을 때는 해당 워크스페이스의 읽지 않음 표시가 해제됨.
  - 부작용: 클릭할 때마다 원격 워크스페이스에 셸이 1~2초 떴다가 종료됨. 전환이 실패해도 터미널은 닫도록 처리.
  - 로컬 세션 클릭은 `worktree activate`로 정상 동작(실행 후 활성 워크스페이스가 바뀌는 것을 확인).

### 5단계: 다듬기 (구현 완료, 2026-11-12)

**라운지 (커피, 수다, 헬스장)**
- 라운지 배치(왼쪽부터): 커피 카운터 → 수다 테이블, 소파(스탠드 포함), 화분을 폭이 남는 만큼 반복 → 오른쪽 끝에 헬스장(러닝머신, 아령 거치대, 고무 매트 바닥). 순서는 `scene.ts`의 `LOUNGE_PATTERN`.
- 헬스장은 라운지 폭이 170 장면 픽셀 이상일 때만 생김. 좁으면 생략.
- 쉬는 캐릭터의 행동(`office.ts`의 `pickLounge`): 커피 18%, 수다 테이블 30%, 소파 16%, 운동 18%, 나머지는 서성이기. 자리가 차 있으면 서성이기로 넘어감.
- 수다: 서서 쓰는 높은 테이블 양옆에 한 명씩. 혼자면 커피를 마시며 기다리고, 상대가 오면 1.5초마다 번갈아 손짓하며 말풍선(줄글 아이콘)을 띄움. 혼자 있는 테이블에 먼저 합류하도록 해 짝이 잘 맞춰짐. 대화 중에는 70% 확률로 더 머묾.
- 운동: 러닝머신에서 달리기(벨트가 움직임), 아령을 머리 위로 들었다 내리기.
- 확인됨(캡처): 수다 두 쌍과 말풍선, 러닝머신 달리기, 아령 들기, 커피, 소파.

**도구 아이콘**
- 작업 중 말풍선이 도구 아이콘(1.7초)과 점 세 개(0.9초)를 번갈아 표시. 도구 이름의 일부로 여섯 종류(터미널, 편집, 읽기, 검색, 웹, 에이전트)로 분류(`sprites.ts`의 `toolKind`). 분류되지 않으면 점만 표시.
- 확인됨(캡처): 읽기, 검색, 편집 아이콘.

**설정 (트레이 메뉴)**
- 설정 창 대신 트레이 메뉴에 넣음: "퇴근 기준"(10분, 30분, 1시간, 3시간, 하루, 퇴근시키지 않음), "최대 인원"(6, 12, 20, 30명), "Windows 시작 시 실행".
- 자동 실행은 설치본이면 자기 자신을, 개발 실행이면 electron.exe에 프로젝트 폴더를 넘기는 형태로 등록.
- 확인 못 함: 메뉴를 직접 눌러 바꾸는 것, 자동 실행 등록 후 재부팅.

**드래그로 폭 조절**
- 띠의 왼쪽/오른쪽 끝 8px에 커서를 올리면 노란 손잡이가 보이고, 끌면 그쪽 끝만 움직임(반대쪽 고정). 폭은 배율의 배수로 맞추고 최소 폭은 작업 영역의 20%.
- 놓으면 위치와 폭을 설정에 저장(`align: custom`, `leftFraction`). 트레이의 "위치"에 "직접 조절"로 표시되고, 폭이나 위치 프리셋을 고르면 프리셋으로 돌아감.
- 확인 못 함: 실제 드래그 동작 전체. 마우스를 직접 움직여야 해서 사용자 확인 필요.

**설치 파일**
- `npm run dist`로 `release/Taskbar Office Setup 0.1.0.exe`(약 115MB, NSIS 원클릭 설치, 사용자 단위 설치) 생성. 아이콘은 트레이와 같은 픽셀 그림으로 `scripts/make-icon.mjs`가 만듦.
- 설치본과 개발 실행은 같은 설정 폴더(`%APPDATA%\orca-taskbar-office`)를 쓰고, 동시에 하나만 실행됨.
- 코드 서명은 하지 않음. 실행 시 Windows SmartScreen 경고가 뜰 수 있음.
- 확인됨: 빌드 성공, 압축 해제본(`release/win-unpacked/Taskbar Office.exe`)이 실행되어 Orca에 연결되고 기존 설정을 그대로 읽음.
- 확인 못 함: 설치 파일을 실제로 실행해 설치하는 과정.

### 그림 개선 (2026-11-12, 구현 완료)

**에셋팩을 쓰지 않기로 한 이유**
- 무료 에셋팩을 조사했으나, 옆에서 본 사무실 그림에 타이핑·운동 같은 동작까지 갖춘 무료 팩은 찾지 못함.
- 찾은 무료 사무실 팩은 거의 모두 위에서 내려다본 시점이고 캐릭터 동작은 서 있기와 걷기뿐: 2dPig Pixel Office(CC0), Kenney RPG Urban Pack·Roguelike Indoors(CC0), LimeZu Modern Interiors 무료판(개인 프로젝트 전용), HappyHustle Modern Rooms & People(상업 사용 가능, 재배포 금지).
- 결정: 옆 시점과 직접 그린 그림을 유지하고 품질을 올림. 에셋팩으로 바꾸려면 시점 전환과 동작 포기가 필요함.

**바꾼 것**
- 외곽선: 캐릭터와 가구에 어두운 1픽셀 외곽선을 자동으로 입힘(`pixel.ts`의 `addOutline`). 밝은 배경과 어두운 배경 어디서나 그림이 묻히지 않음. 커서를 올린 캐릭터는 외곽선이 노란색으로 바뀜(이전의 노란 사각형 대체).
- 캐릭터 명암: 옷의 등 쪽과 밑단 그림자, 가슴 하이라이트, 목선, 턱 그림자, 볼 홍조, 머리카락 윤기, 뒤쪽 다리 어둡게. 발밑 그림자 추가.
- 가구 디테일: 의자 방석 색(4종), 책상 서랍과 머그컵, 모니터 베젤, 스탠딩 데스크 발 매트, 스툴 방석, 빈백 음영, 화분 3단 명암, 화이트보드 펜 받침, 문짝 패널, 커피 카운터 손잡이와 컵 더미, 소파 방석 이음매와 쿠션.
- 움직이는 효과: 커피머신에서 피어오르는 김, 스탠드 불빛 번짐, 코드 줄이 두 색으로 깜빡이는 화면.
- 바닥: 오피스는 이음매가 있는 나무 마루, 라운지는 점무늬 카펫, 헬스장은 고무 매트.
- 서성이는 캐릭터가 수다 테이블 자리와 겹치지 않게 함.

**구조**
- `scene.ts`는 배치 계산만, 그리기는 `scene-art.ts`로 분리.
- 움직이지 않는 가구는 배치가 바뀔 때 한 번만 그려 외곽선을 입혀 두고, 매 프레임에는 그 그림을 붙인 뒤 움직이는 부분만 덧그림. 캐릭터는 매 프레임 작은 캔버스에 그려 외곽선을 입힘.

**확인 방법**
- 화면이 잠겨 있어 화면 캡처를 쓸 수 없었음. 그래서 장면 캔버스를 PNG로 저장하는 개발용 기능을 추가: `TASKBAR_OFFICE_SNAPSHOT=<png 경로>`(대기 시간은 `TASKBAR_OFFICE_SNAPSHOT_DELAY`, 기본 7000ms).
- 확인됨(스냅샷): 전원 작업 데모의 오피스, 전원 휴식 데모의 라운지를 밝은 배경과 어두운 배경 위에서 확인.
- 확인 못 함: 실제 화면에서 보이는 모습, 커서를 올렸을 때의 노란 외곽선.

## 7. 나중에 생각할 것

- 서브에이전트(`children`)를 작은 캐릭터나 인턴으로 표시.
- 원격 환경 세션을 별도 층이나 방으로 구분하거나, 캐릭터 외형으로 로컬/원격을 구분.
- 워크스페이스별로 책상 구역을 나누고 이름표 달기.
- 오피스에서 직접 메시지 보내기, 에이전트 실행.
- 전체 화면 앱(게임, 발표) 실행 중에는 자동으로 숨기기.
